设计说明与维护方法

站务手册

记录资源簿的关键决策、文件配置、内容更新、投稿审核和部署排错方法，供后续维护者直接查阅。

目录 项目概况设计决策文件结构 维护资源修改站点投稿与审核 部署方法故障排查边界与限制

项目概况

资源簿是一个不足 100 人使用的小型链接导航。网站只保存资源名称、说明、分类、标签和外部链接，不代理下载，也不保管第三方资源。

  • 组织：IMakerStudioCN
  • 仓库：IMakerStudioCN/IMakerStudioCN.github.io
  • 网站：https://imakerstudiocn.github.io/
  • 分支：main
  • 托管：GitHub Pages
  • 投稿：飞书公开表单

设计决策

不使用 Linkwarden

用户少且只分享外部链接。完整书签服务需要服务器、数据库和运维，超出实际需求。

采用纯静态站

HTML、CSS、JavaScript 和 JSON 即可完成展示、分类与搜索，没有运行中的后端。

使用组织根站

仓库命名为组织名加 .github.io，因此网站直接使用组织根域名。

投稿数据放在飞书

访客不必登录 GitHub。公开表单收集内容，原始数据表只向维护者开放。

搜索在浏览器完成

资源数量较少，前端直接读取 JSON 并筛选，不需要搜索服务或数据库。

保持低依赖

不引用海外字体、图标库或前端框架，降低国内网络环境下的加载风险。

视觉方向

界面采用信息优先的编辑式布局，使用浅色背景、深绿色强调色、系统中文字体和低强度交互。主要依靠排版、留白和细分隔线建立层级。

已经解决的问题

  • 长中文标题曾挤出桌面视口，已通过调整断行、字号和网格最小宽度修复。
  • 组织根站与项目子路径均使用相对地址，迁移仓库名称时不需要重写资源路径。
  • GitHub 自定义工作流与内置 Pages 工作流曾重复部署，现已删除自定义工作流，只使用内置部署。
  • 飞书内部数据表地址不能用于访客投稿，网站现使用 /share/base/form/ 开头的公开填写链接。
  • GitHub HTTPS 推送曾受网络影响，当前仓库已通过 SSH 建立远程连接。

文件结构

  • index.html：首页结构、站名、介绍和导航。
  • resources.json：资源数据、最后更新时间和投稿地址。
  • app.js：读取资源、分类筛选、关键词搜索和空状态。
  • styles.css：颜色、排版、响应式布局和手册样式。
  • maintenance.html：当前站务手册。
  • 404.html：无效地址提示页。
  • .nojekyll：让 GitHub Pages 直接发布静态文件。
  • .github/ISSUE_TEMPLATE/：备用的 GitHub 推荐表单。

维护资源

  1. 在 GitHub 仓库打开 resources.json。
  2. 点击铅笔图标编辑文件。
  3. 新增、修改或删除资源对象。
  4. 同步修改顶部的 updatedAt。
  5. 提交到 main，等待 Pages 自动更新。
{
  "name": "资源名称",
  "description": "说明它解决什么问题、适合哪些人。",
  "url": "https://example.com/",
  "category": "学习",
  "tags": ["教程", "免费"]
}

相邻资源对象之间需要英文逗号，最后一条资源后面不要加逗号。新增分类无需修改代码，分类按钮会自动生成。

修改站点

站名与介绍

编辑 index.html 中的 <title>、左上角品牌文字、首页标题、简介和页脚。修改站名时应同时检查 maintenance.html 与 404.html。

颜色

编辑 styles.css 顶部的变量：

--paper: #f4f5f0;
--surface: #ffffff;
--ink: #17201b;
--muted: #667069;
--line: #d7dcd5;
--accent: #126b4b;
--accent-soft: #dcebe3;

保持单一强调色，并检查按钮文字、正文和背景的可读性。

投稿与审核

首页右上角“推荐资源”读取 resources.json 中的 submitUrl。当前地址为飞书公开填写表单。

修改飞书表单

调整问题、选项、顺序和必填状态不会影响网站。只要公开填写链接不变，网站无需更新。删除并重建表单、关闭公开分享或生成新链接时，需要更新 submitUrl。

查看投稿

维护者登录飞书并打开原多维表格，在非表单视图中查看记录。每次投稿会新增一行。建议增加以下管理员字段：

  • 审核状态：待审核、已收录、不收录。
  • 审核备注：记录修改或拒绝原因。
  • 处理日期：记录完成时间。

可在飞书自动化中设置“新增记录时发送飞书消息”，避免漏看新投稿。

不要把飞书内部数据表地址公开给访客。公开填写链接可以分享，原始数据表应限制为维护者可见。

部署方法

  1. 在 GitHub 网页中编辑文件并提交到 main。
  2. 打开仓库的 Actions 页面查看 pages build and deployment。
  3. 绿色对勾表示发布成功，黄色圆点表示运行中，红色叉号表示失败。
  4. 发布通常需要 1-3 分钟。完成后强制刷新网站。

本项目只保留 GitHub Pages 内置工作流。不要再次添加自定义 Pages 部署工作流，否则可能争抢同一个部署环境。

故障排查

网站仍显示旧内容

先查看 Actions 是否成功。成功后使用 Windows 的 Ctrl + F5 或 macOS 的 Command + Shift + R 强制刷新。

资源列表无法显示

检查 resources.json 的英文逗号、双引号和方括号。JSON 格式错误会导致整个列表读取失败。

投稿按钮打不开

用未登录飞书的浏览器测试公开表单。确认分享范围是“互联网上获得链接的人”，并检查 submitUrl 是否仍为有效地址。

Pages 部署失败

检查是否重新加入了其他 Pages 工作流。保持仓库 Settings 中的 Pages 来源为默认分支，并只保留内置部署。

边界与限制

  • GitHub Pages 是公开静态站，不适合保存密码、内部链接或个人敏感信息。
  • 网站没有账号、评论和实时数据库。投稿依赖飞书表单。
  • github.io 在中国大陆的访问速度与稳定性不能保证。
  • 本站只应分享合法的外部链接，不代理文件，不绕过付费或访问限制。
  • 内容规模明显增长后，应先优化分类和数据维护流程，再考虑引入后端。
