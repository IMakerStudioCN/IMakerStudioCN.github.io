配置、维护与交接

站务手册

按文件和页面位置说明如何修改网站。新维护者具备组织仓库写入权限和飞书表格访问权限后，即可完成日常维护。

目录交接清单文件与权限标题与文案资源与封面外观配置投稿与审核发布与回退故障排查安全边界

交接清单

交接前逐项确认，避免新维护者只能看到网站却无法管理数据。

  1. 把新维护者加入 GitHub 组织 IMakerStudioCN，确认其对仓库 IMakerStudioCN.github.io 有写入权限。
  2. 共享飞书多维表格，至少授予查看投稿和修改审核字段的权限。
  3. 分别打开网站、仓库、Actions、站务手册和投稿表单，确认均可访问。
  4. 让新维护者试改一条测试资源，验证 JSON、提交、Pages 发布和网页刷新全流程。
  5. 不要在仓库或手册中保存密码、令牌、私人联系方式等敏感信息。
  • 网站：https://imakerstudiocn.github.io/
  • 仓库：https://github.com/IMakerStudioCN/IMakerStudioCN.github.io
  • 发布分支：main
  • 托管方式：GitHub Pages 内置部署

文件与权限

  • index.html：首页标题、导航、介绍、搜索区标题、维护原则和页脚。
  • resources.json：更新时间、投稿地址、默认封面和全部资源。
  • app.js：资源卡片、分类按钮、搜索、计数和数据读取。
  • styles.css：颜色、字号、间距、封面透明度和手机布局。
  • assets/resource-cover.webp：卡片共用的默认封面。
  • maintenance.html：网页手册，维护流程变化后应同步更新。
  • README.md：仓库首页交接手册，应与网页手册同步。
  • 404.html：无效地址页的标题、提示语和返回按钮。
  • .nojekyll：让 Pages 直接发布静态文件，保留为空文件。

日常维护通常只编辑 resources.json。修改页面文字、外观或功能时才编辑其他文件。

标题与文案配置

首页 index.html

  • 浏览器标签标题：查找 <title>资源簿</title>。
  • 搜索引擎摘要：修改 <meta name="description"> 的 content。
  • 左上角站名：修改 class="brand" 内的“资”和“资源簿”；“资”是方形标记。
  • 导航标题：修改 class="header-actions" 中各链接文字；链接地址在对应 href。
  • 首页小标题：查找“少而精的链接收藏”；主标题：查找“找到值得打开的资源”。
  • 首页简介：修改 class="intro-note" 的段落。
  • 统计标签：修改“项资源”“个分类”“最后整理”；数字与日期由脚本填写。
  • 资源区标题：修改“资源索引”“浏览全部”；搜索提示在输入框 placeholder。
  • 空状态：修改 class="empty-state" 内的提示和按钮文字。
  • 页脚：修改 <footer> 内站名、描述和链接。

其他页面

修改站名后，用仓库搜索功能搜索旧站名，并同步修改 maintenance.html、404.html 和 README.md。手册页和 404 页的浏览器标题均在各自文件的 <title>。

资源与封面

  1. 在仓库打开 resources.json，点击铅笔图标。
  2. 复制一条完整资源对象，在上一条结尾补英文逗号。
  3. 填写字段并更新顶部 updatedAt。
  4. 提交到 main，等待 Actions 发布。
{
  "name": "资源名称",
  "description": "说明它解决什么问题、适合哪些人。",
  "url": "https://example.com/",
  "category": "学习",
  "tags": ["教程", "免费"],
  "cover": "./assets/example-cover.jpg"
}
  • name：卡片大标题，建议不超过 24 个中文字符。
  • description：卡片说明，建议 30 至 70 个中文字符。
  • url：点击后的外部地址，必须保留 https://。
  • category：分类按钮名称；新分类会自动生成按钮，名称应保持一致。
  • tags：用于展示和搜索；卡片显示前两个，搜索读取全部。
  • cover：可选。填写后覆盖默认封面；省略时使用顶部 defaultCover。

更换封面

全站默认封面在 resources.json 的 defaultCover。把新图片上传到 assets，再修改地址。建议使用横向 JPG、PNG 或 WebP，宽度 1200 至 2000 像素，文件小于 500 KB，不使用有版权风险、商标或难以阅读文字的图片。

单条资源可增加 cover。透明度在 styles.css 的 .resource-cover 中修改，默认值为 opacity: .16；悬停值在 .resource-card:hover .resource-cover。

JSON 只能使用英文双引号和英文标点。最后一条资源后不要加逗号。图片路径区分大小写，文件名建议只用小写英文、数字和连字符。

外观配置

颜色变量

--paper: #f4f5f0;       /* 页面背景 */
--surface: #ffffff;     /* 悬停表面 */
--ink: #17201b;         /* 主文字和深色按钮 */
--muted: #667069;       /* 次要文字 */
--line: #d7dcd5;        /* 分隔线 */
--accent: #126b4b;      /* 强调色 */
--accent-soft: #dcebe3; /* 聚焦状态浅色 */
--radius: 14px;         /* 圆角基准 */

变量位于 styles.css 顶部。修改后检查首页、按钮、搜索框、卡片和代码块的对比度。

字号与间距

  • 首页主标题：.intro h1
  • 资源区标题：.catalog-head h2
  • 卡片标题：.resource-card h3
  • 卡片高度和内边距：.resource-card 的 min-height 与 padding
  • 最大页面宽度：.site-header, main, footer 的 width
  • 手机布局：文件底部 @media (max-width: 760px)

每次改字号、标题或卡片后，同时检查约 375 像素宽的手机页面是否横向溢出。

投稿与审核

首页“推荐资源”地址来自 resources.json 的 submitUrl。更换飞书表单时只修改此值。

修改飞书表单

调整问题、顺序和必填状态不会影响网站。若重建表单、关闭公开分享或生成新链接，必须把新的公开填写地址写入 submitUrl。地址应包含 /share/base/form/，不要使用内部多维表格地址。

审核流程

  1. 在飞书普通数据视图查看新记录。
  2. 检查链接可用性、合法性和重复情况。
  3. 润色名称及说明，统一分类和标签。
  4. 把通过记录写入 resources.json 并更新日期。
  5. 把审核状态改为“已收录”或“不收录”，填写备注和处理日期。

建议保留“审核状态、审核备注、处理日期、处理人”四个管理字段，并设置新增记录通知。原始数据表只向维护者开放。

发布与回退

  1. 通过 GitHub 网页或本地 Git 提交文件到 main。
  2. 在 Actions 查看 pages build and deployment。
  3. 绿色对勾后等待约 1 至 3 分钟，再强制刷新。
  4. 测试首页、修改过的资源、投稿按钮和站务手册。

项目只使用 GitHub Pages 内置工作流，不要添加第二套 Pages 部署流程。需要回退时，对错误提交使用 GitHub 的 Revert 功能生成反向提交；不要删除仓库或强制重置 main。

故障排查

网站仍显示旧内容

先确认 Actions 成功，再用 Windows 的 Ctrl + F5 或 macOS 的 Command + Shift + R 强制刷新。

资源列表不显示

优先检查 resources.json 的逗号、双引号和括号。可把完整内容粘贴到 JSON 校验工具。

封面不显示

检查图片是否已提交、路径大小写是否一致。单条失败检查 cover；全部失败检查 defaultCover。

投稿按钮打不开

用未登录飞书的浏览器测试，确认公开分享仍开启且 submitUrl 是公开表单地址。

Pages 部署失败

查看失败步骤。若构建成功但部署失败，可等待后重试；同时检查是否有重复工作流或 Pages 来源被修改。

安全边界

  • GitHub Pages 和仓库内容均公开，不保存密码、令牌、内部链接或个人敏感信息。
  • 网站没有账号、评论、数据库和权限系统，投稿依赖飞书。
  • 只分享合法外部链接，不代理文件，不绕过付费、版权或访问限制。
  • 新增图片前确认有使用权并压缩，避免仓库体积持续增长。
  • github.io 在中国大陆的访问速度和稳定性无法保证。
