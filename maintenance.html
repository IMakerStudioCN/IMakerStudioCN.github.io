配置、维护与交接

站务手册

按文件和页面位置说明如何修改网站，并提供保留现有依赖的最小可运行交接和丢失全部账号依赖后的完全重建交接。

目录交接清单文件与权限标题与文案扩展页面资源、类型与标签外观配置投稿与审核发布与回退故障排查安全边界

管理交接

完全交接用于旧管理者的 GitHub、飞书表格、应用和令牌全部不可用时重建项目；最小可运行交接用于所有现有依赖继续存在时授权新管理者接手。

完全交接方案

项目文件

  1. 从公开仓库或事先保留的 Git 镜像/ZIP 取得完整项目，保留 resources.json、.github/workflows/、scripts/、.pages.yml、.nojekyll 和所有网站文件。
  2. 已发布资源可从 resources.json 恢复；原飞书不可访问时，未同步投稿只能从事先导出的表格备份恢复。
  3. 重建后更新 submitUrl，并全局替换旧组织名、仓库名和网址。

飞书

  1. 用新账号/租户创建多维表格和公开表单，按“飞书字段”章节重建全部字段，必要时导入备份。
  2. 创建并发布企业自建应用，授予多维表格读写权限，再把应用添加为表格协作者。
  3. 记录新的 App ID、App Secret、App Token、Table ID 和可选 View ID，只将它们保存到 GitHub Secrets/Variables 或密码管理器。
  4. 用未登录浏览器验证新公开表单，将其地址写入 resources.json 的 submitUrl。

GitHub

  1. 用新账号/组织创建公开仓库；用户站点仓库名应为 <新所有者>.github.io。
  2. 推送完整项目到 main，启用从分支根目录发布的 GitHub Pages。
  3. 创建 Secrets：FEISHU_APP_ID、FEISHU_APP_SECRET、FEISHU_MERGE_TOKEN；合并 PAT 只授权新仓库的 Contents 和 Pull requests 读写权限。
  4. 创建 Variables：FEISHU_APP_TOKEN、FEISHU_TABLE_ID、FEISHU_VIEW_ID、FEISHU_SYNC_MODE=all 及必要的字段映射。
  5. 开启 Actions 写权限和创建/approve PR 权限，为 Pages CMS GitHub App 授权新仓库。
  6. 用测试投稿验收“公开表单 → 飞书审核 → 自动 PR/合并 → Pages”全链路。

最小可运行交接方案

项目文件

  1. 新管理者克隆现有仓库，阅读手册和 resources.json，不变更当前地址。
  2. 试改一条测试资源，验证 JSON、提交、Pages 和网页刷新。
  3. 确认仓库中没有密码、令牌或飞书内部链接。

飞书

  1. 共享现有多维表格，授予新管理者查看投稿以及修改审核/同步状态的权限。
  2. 确认自建应用已发布、仍是表格协作者，公开表单在未登录状态下可提交。
  3. 由新管理者完成一条测试投稿的查看、审核和同步状态检查。

GitHub

  1. 将新管理者加入 IMakerStudioCN 并授予本仓库写入权限，确认可查看 Actions 和 Pages。
  2. 保留现有 Secrets/Variables，确认名称齐全且最近同步 Action 成功；不在文档中复制 Secret 值。
  3. 确认新管理者可用 GitHub 登录 Pages CMS 并编辑本仓库。
  4. 可行时由新管理者创建自己的细粒度 PAT 替换 FEISHU_MERGE_TOKEN，减少对旧账号的依赖。
  5. 验收网站、仓库、Actions、Pages、在线手册、Pages CMS 和投稿表单。

文件与权限

  • index.html：首页标题、导航、介绍、资源区标题、维护原则和页脚。
  • submission.html：访客飞书投稿入口。
  • submission.js：从 resources.json 读取当前飞书表单地址。
  • admin.html：管理者在线编辑、投稿审核与发布入口。
  • resources.json：更新时间、投稿地址、默认封面和全部资源。
  • app.js：资源卡片、分类按钮、搜索、计数和数据读取。
  • .pages.yml：Pages CMS 管理者编辑器的字段配置。
  • scripts/sync-feishu-submissions.mjs：读取飞书审核记录并写入资源数据。
  • .github/workflows/sync-feishu-submissions.yml：定时创建并自动合并 PR，并回写飞书同步状态。
  • styles.css：颜色、字号、间距、封面透明度和手机布局。
  • assets/resource-cover.webp：卡片共用的默认封面。
  • maintenance.html：网页手册，维护流程变化后应同步更新。
  • README.md：仓库首页交接手册，应与网页手册同步。
  • README.txt：纯文本交接手册，应同步更新。
  • 404.html：无效地址页的标题、提示语和返回按钮。
  • .nojekyll：让 Pages 直接发布静态文件，保留为空文件。

submission.html 现仅用于访客投稿；管理者入口已独立为 admin.html。日常维护通常只编辑 resources.json，修改页面文字、外观或功能时才编辑其他文件。

标题与文案配置

首页 index.html

  • 浏览器标签标题：查找 <title>资源簿</title>。
  • 搜索引擎摘要：修改 <meta name="description"> 的 content。
  • 左上角站名：修改 class="brand" 内的“资”和“资源簿”；“资”是方形标记。
  • 导航标题：修改 class="header-actions" 中各链接文字；链接地址在对应 href。
  • 首页小标题：查找“少而精的链接收藏”；主标题：查找“找到值得打开的资源”。
  • 首页简介：修改 class="intro-note" 的段落。
  • 统计标签：修改“项资源”“个分类”“最后整理”；数字与日期由脚本填写。
  • 资源区标题：修改“资源索引”“浏览全部”；搜索提示在输入框 placeholder。
  • 空状态：修改 class="empty-state" 内的提示和按钮文字。
  • 页脚：修改 <footer> 内站名、描述和链接。

其他页面

修改站名后，用仓库搜索功能搜索旧站名，并同步修改 maintenance.html、404.html 和 README.md。手册页和 404 页的浏览器标题均在各自文件的 <title>。

扩展页面

新增说明页、专题页或公告页时，优先复制 maintenance.html 的基础结构，以保留页头、页脚、无障碍跳转和响应式样式。

  1. 复制现有 HTML 文件，改成小写英文文件名，例如 guide.html；不要使用空格或中文文件名。
  2. 修改 <title>、meta description、正文标题和内容。
  3. 保留 ./styles.css 相对路径；页面需要交互时再引用独立脚本。
  4. 在 index.html 的 header-actions 或页脚加入 ./guide.html 入口。
  5. 若所有页面都需要入口，同步修改 maintenance.html 和 404.html。
  6. 发布后访问完整网址，例如 https://imakerstudiocn.github.io/guide.html，检查桌面和手机布局。

分类、类型和标签写在 resources.json。只有内容需要独立正文和独立网址时才创建 HTML 页面。

资源、类型与标签

  1. 在仓库打开 resources.json，点击铅笔图标。
  2. 复制一条完整资源对象，在上一条结尾补英文逗号。
  3. 填写字段并更新顶部 updatedAt。
  4. 提交到 main，等待 Actions 发布。
{
  "name": "资源名称",
  "description": "说明它解决什么问题、适合哪些人。",
  "url": "https://example.com/",
  "category": "学习",
  "type": "网站",
  "tags": ["教程", "免费"],
  "cover": "./assets/example-cover.jpg"
}
  • name：卡片大标题，建议不超过 24 个中文字符。
  • description：卡片说明，建议 30 至 70 个中文字符。
  • url：点击后的外部地址，必须保留 https://。
  • category：内容主题，如“开发、设计、学习、效率”；第一排按钮自动读取所有分类。
  • type：资源载体，如“网站、网盘链接、在线工具、文档、视频、课程平台”；第二排按钮自动读取所有类型。
  • tags：更细的关键词；卡片显示前两个，搜索读取全部。
  • cover：可选。填写后覆盖默认封面；省略时使用顶部 defaultCover。

扩展分类和资源类型

直接在资源对象的 category 或 type 中写入新名称，页面会自动生成按钮，不需要修改 index.html 或 app.js。同一含义必须使用完全相同的文字。重命名时搜索并一次性修改所有相关资源。

扩展标签

在 tags 数组中增加英文双引号包裹的标签，并用英文逗号分隔，例如 ["教程", "免费", "中文"]。建议每条保留 2 至 5 个短标签，不重复分类或类型。标签会参与搜索但不会生成筛选按钮；需要按钮时应使用 category 或 type。

网盘链接建议

网盘资源的 type 统一写成“网盘链接”。说明中写清内容、格式和更新时间；提取码可以写在说明中，但不要收录需要私人账号、个人权限或来源不明的文件。链接失效后及时删除或替换。

更换封面

全站默认封面在 resources.json 的 defaultCover。把新图片上传到 assets，再修改地址。建议使用横向 JPG、PNG 或 WebP，宽度 1200 至 2000 像素，文件小于 500 KB，不使用有版权风险、商标或难以阅读文字的图片。

单条资源可增加 cover。透明度在 styles.css 的 .resource-cover 中修改，默认值为 opacity: .16；悬停值在 .resource-card:hover .resource-cover。

JSON 只能使用英文双引号和英文标点。最后一条资源后不要加逗号。图片路径区分大小写，文件名建议只用小写英文、数字和连字符。

变量位于 styles.css 顶部。修改后检查首页、按钮、搜索框、卡片和代码块的对比度。

字号与间距

  • 首页主标题：.intro h1
  • 资源区标题：.catalog-head h2
  • 卡片标题：.resource-card h3
  • 卡片高度和内边距：.resource-card 的 min-height 与 padding
  • 最大页面宽度：.site-header, main, footer 的 width
  • 手机布局：文件底部 @media (max-width: 760px)

每次改字号、标题或卡片后，同时检查约 375 像素宽的手机页面是否横向溢出。

投稿与审核

网站将两个角色拆为独立页面：submission.html 仅供访客使用飞书公开表单投稿；admin.html 集中提供 Pages CMS、投稿审核和发布说明。

访客飞书投稿

飞书表单地址来自 resources.json 的 submitUrl。调整现有表单问题、顺序和必填状态不会影响网站；重建表单或生成新链接时必须更新该值。公开地址应包含 /share/base/form/。

飞书字段

数据表需要下列字段。资源字段可以显示在公开表单中；审核状态和同步状态只供管理者使用：

  • 资源名称：单行文本，必填。
  • 资源链接：超链接或文本，必填。
  • 资源简介：多行文本，必填。
  • 内容分类：单选或文本，必填。
  • 资源类型：单选或文本，必填。
  • 标签：多选或逗号分隔文本，必填。
  • 封面地址：可选，不建议让匿名投稿者上传仓库文件。
  • 审核状态：管理用单选字段，选项为“待审核、已通过、不收录”。
  • 同步状态：管理用单行文本字段，初始为空，由 Actions 回写 PR 地址；不要设为单选字段。

资源链接 可粘贴含中文路径/参数的 HTTP/HTTPS 链接或完整网盘分享文本。同步脚本会先清理零宽字符和特殊空格，过滤链接外的说明文字，只将提取到的链接转换为标准百分号编码。提取码/访问密码建议放在“资源简介”。无法解析的链接会被跳过，Action 日志会显示对应飞书记录 ID。

审核并自动发布

自动合并链路已于 2026-08-20 完成线上测试，已验证普通 PR 创建、飞书状态回写、PR 自动合并、临时分支删除和 Pages 更新。

  1. 管理者在飞书检查链接、版权、重复内容和文字质量。
  2. 统一分类、类型和标签，将 审核状态 改为“已通过”；此操作即表示最终发布授权。
  3. Actions 每两小时自动检查，也可在 Actions 页面手动运行 Sync approved Feishu submissions。
  4. 默认处理全部“已通过且同步状态为空”记录；缺少字段的记录会被跳过，日志显示记录 ID、投稿时间和中文字段名。
  5. 校验通过后脚本写入临时分支并创建普通 PR。
  6. Actions 把同步状态回写为“已提交审核：PR 地址”，再自动合并 PR 和删除临时分支，Pages 随后自动发布。
  7. 自动合并失败时 PR 会保留；检查令牌权限、分支保护或合并冲突并手动恢复。只有关闭 PR 且需要重新生成时才清空飞书同步状态。

飞书开放平台配置

  1. 创建企业自建应用，申请多维表格读取和编辑权限并发布版本。
  2. 把应用添加为目标多维表格协作者。
  3. 在 GitHub 仓库 Settings → Secrets and variables → Actions 中添加 Secrets：FEISHU_APP_ID、FEISHU_APP_SECRET、FEISHU_MERGE_TOKEN。合并令牌使用仅授权当前仓库的细粒度 PAT，授予 Contents 和 Pull requests 读写权限。
  4. 添加 Variables：FEISHU_APP_TOKEN、FEISHU_TABLE_ID、FEISHU_VIEW_ID。
FEISHU_APP_TOKEN=TDDCbNKFUa1d7QsKX7vcrJinnhe
FEISHU_TABLE_ID=tblyK8zKwJX3F91g
FEISHU_VIEW_ID=vew3HOr4oa

字段名采用上面的默认中文名称时无需额外配置。若实际字段名不同，可设置 FEISHU_FIELD_NAME、FEISHU_FIELD_URL、FEISHU_FIELD_DESCRIPTION、FEISHU_FIELD_CATEGORY、FEISHU_FIELD_TYPE、FEISHU_FIELD_TAGS、FEISHU_FIELD_COVER、FEISHU_FIELD_REVIEW、FEISHU_FIELD_SYNC 和 FEISHU_FIELD_CREATED_TIME。同步默认使用 FEISHU_SYNC_MODE=all，处理全部“审核状态=已通过且同步状态为空”的投稿；仅需每次处理最新一条时改为 latest。最后进入 Settings → Actions → General → Workflow permissions，启用“Allow GitHub Actions to create and approve pull requests”，否则只能创建分支，不能创建审核 PR。

管理者在线编辑

  1. 打开 admin.html 并选择“进入 Pages CMS”。
  2. 使用 GitHub 登录 Pages CMS。
  3. 安装或授权 Pages CMS GitHub App，只允许访问当前仓库。
  4. 选择 IMakerStudioCN/IMakerStudioCN.github.io。
  5. 编辑“资源管理”，保存前更新最后整理日期。
  6. 保存后检查 Actions 和线上网站。

FEISHU_APP_SECRET 只能保存在 GitHub Actions Secret 中，不能写入网页、README、脚本默认值或公开 Issue。

发布与回退

  1. 通过 GitHub 网页或本地 Git 提交文件到 main。
  2. 在 Actions 查看 pages build and deployment。
  3. 绿色对勾后等待约 1 至 3 分钟，再强制刷新。
  4. 测试首页、修改过的资源、投稿按钮和站务手册。

项目只使用 GitHub Pages 内置工作流，不要添加第二套 Pages 部署流程。需要回退时，对错误提交使用 GitHub 的 Revert 功能生成反向提交；不要删除仓库或强制重置 main。

故障排查

网站仍显示旧内容

先确认 Actions 成功，再用 Windows 的 Ctrl + F5 或 macOS 的 Command + Shift + R 强制刷新。

资源列表不显示

优先检查 resources.json 的逗号、双引号和括号。可把完整内容粘贴到 JSON 校验工具。

封面不显示

检查图片是否已提交、路径大小写是否一致。单条失败检查 cover；全部失败检查 defaultCover。

投稿按钮打不开

用未登录飞书的浏览器测试，确认公开分享仍开启且 submitUrl 是公开表单地址。

飞书同步工作流失败

先检查五个必需配置是否存在，再确认自建应用已发布、具有多维表格读写权限且已成为表格协作者。字段错误时核对 GitHub Variables 中的字段映射。PR 未自动合并时，检查 FEISHU_MERGE_TOKEN 是否过期、是否具有必需权限，以及 main 分支保护和合并冲突。合并成功但网站未更新时，检查 pages build and deployment 是否由合并提交触发，并确认合并步骤使用 FEISHU_MERGE_TOKEN 而非内置 GITHUB_TOKEN。

飞书记录没有生成 PR

确认审核状态严格等于“已通过”、同步状态为空、链接未在 resources.json 中出现，并查看 Actions 日志中的“跳过记录”。

Pages 部署失败

查看失败步骤。若构建成功但部署失败，可等待后重试；同时检查是否有重复工作流或 Pages 来源被修改。

安全边界

  • GitHub Pages 和仓库内容均公开，不保存密码、令牌、内部链接或个人敏感信息。
  • 网站没有账号、评论、数据库和权限系统，投稿依赖飞书。
  • 只分享合法外部链接，不代理文件，不绕过付费、版权或访问限制。
  • 新增图片前确认有使用权并压缩，避免仓库体积持续增长。
  • github.io 在中国大陆的访问速度和稳定性无法保证。
